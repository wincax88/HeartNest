# HeartNest 欢迎页布局优化设计

日期：2026-09-30

## 背景

微信小程序欢迎页在当前手机尺寸下，底部功能卡、主按钮、次入口和分页点间距偏紧。多个区域分别使用绝对定位，导致视觉层级不够清晰，也增加了不同屏幕高度和底部安全区下发生拥挤或重叠的风险。

本次采用已确认的 A「舒展分层」方案：保留现有夜景背景、品牌气质、文案和业务流程，重点优化底部交互区，并对标题、遮罩和背景裁切做必要的协调性微调。

## 目标

- 建立清晰的底部纵向层级：功能卡、主按钮、次入口、分页指示器。
- 确保微信小程序常见屏幕尺寸及底部安全区下不发生遮挡或重叠。
- 保持主按钮为页面最醒目的行动入口。
- 保留现有轮播、点击和跳转行为，不引入新的业务状态。
- 继续兼容 H5、App 和微信小程序构建目标。

## 非目标

- 不更换背景图片、品牌标识或主色系。
- 不修改欢迎页文案和轮播页数量。
- 不改变“开始体验”和“我先看看”的目标页面。
- 不增加新的接口、数据模型或后端逻辑。

## 视觉与布局设计

### 整体结构

页面继续使用全屏夜景背景和渐变遮罩。品牌区固定在顶部安全区下方；标题与说明保持在画面上半部。底部交互内容改为一个统一的自适应内容组，内部按以下顺序排列：

1. 三张功能卡；
2. “开始体验”主按钮；
3. “我先看看”次入口；
4. 轮播分页指示器。

功能卡和操作区不再分别依赖互相无关的绝对定位值。底部内容组统一受底部安全区约束，以减少元素之间的竞争和重叠。

### 功能卡

- 保留三列结构以及原有图标和标签。
- 降低卡片高度和上下内边距，减少对背景主体的遮挡。
- 统一边框透明度、圆角和图标与文字间距。
- 保持玻璃质感，但弱化背景和阴影，使主按钮拥有更高视觉优先级。

### 主按钮

- 保留紫色到粉色、暖橙色的品牌渐变。
- 主按钮宽度与功能卡组对齐，触控高度不低于 88rpx。
- 左侧品牌图标、居中文字和右侧箭头保持稳定布局。
- 右侧箭头容器使用明确的轻透明圆形样式，避免出现类似加载指示器的视觉误读。
- 保持按钮阴影，但降低扩散范围，减少与次入口及分页点的视觉粘连。

### 次入口与分页

- “我先看看”维持低层级文本按钮，但确保触控高度不低于 64rpx。
- 次入口与主按钮、分页点之间使用明确且一致的间距。
- 当前分页状态使用短胶囊，非当前状态使用小圆点；颜色沿用现有紫色体系。
- 分页点只表达轮播状态，不与按钮或装饰元素重叠。

### 背景与文案协调

- 保留现有背景裁切中心，不改变图片资源。
- 调整底部渐变遮罩的过渡区，使文字和交互控件保持足够对比度，同时尽量保留人物与夜景细节。
- 标题和说明只做必要的字号、行高或间距微调，不改变内容。

## 响应式规则

- 默认布局以微信开发者工具截图所示的竖屏手机为基准。
- 底部内容组使用 `env(safe-area-inset-bottom)` 预留安全区。
- 较矮屏幕通过媒体查询依次压缩组间距、功能卡内边距和标题区垂直占用；不隐藏主要操作。
- 较高屏幕保持背景留白，不通过无限增大间距拉散控件。
- 页面最低支持宽度按现有 uni-app 小程序布局体系处理，三列功能卡不得出现横向溢出。

## 交互行为

- 左右滑动继续切换三张欢迎页。
- 分页指示器随 `current` 状态更新。
- “开始体验”和“我先看看”继续调用现有 `enter` 行为并进入同一授权页。
- 不增加自动轮播，避免用户阅读时被打断。

## 可访问性

- 保持文本和背景之间的可读对比度。
- 主按钮及次入口提供足够的触控区域。
- 分页状态不能仅依靠发光效果区分，尺寸形态也必须不同。
- 遵循项目现有的减少动态效果规则，不新增强制动画。

## 实现边界

主要修改 `app/src/pages/onboarding/index.vue` 的结构和局部样式。只有在主按钮通用组件无法实现确认稿效果时，才对 `HnPrimaryButton` 增加向后兼容的样式接口；不得影响其他页面现有按钮。

## 测试与验收

- 为欢迎页增加或更新组件测试，覆盖三项功能、主操作、次入口和分页状态。
- 运行完整单元测试与 TypeScript 类型检查。
- 运行 `npm run build:mp-weixin`，确认微信小程序构建成功且生成的 WXSS 不含已知不兼容选择器。
- 在微信开发者工具中检查至少一个常规屏幕和一个较矮屏幕：底部内容不重叠、不被安全区遮挡、无横向溢出。
- 验证轮播切换、分页反馈以及两个入口的跳转行为保持不变。

## 成功标准

页面在视觉上形成“价值说明 → 功能概览 → 主行动 → 次行动 → 轮播状态”的明确顺序；截图中标出的三处拥挤问题消失，且跨平台构建和现有交互无回归。
