# HeartNest P0/P1/P2 生产化补全设计

## 1. 目标与范围

本设计把当前可演示的 HeartNest 跨平台原型补全为可承载真实用户的生产系统，覆盖微信小程序、App 和 H5。实施分为三个可独立验收、部署和回滚的阶段：安全底座、产品闭环、发布质量。现有 uni-app 页面结构和夜间玻璃质感视觉语言保留，后端身份、数据、安全、支付和通知能力改为服务端可信实现。

本轮目标包括：

- 建立统一用户身份、会话撤销和跨端账号合并能力。
- 将 JSON 文件存储迁移到 HeartNest 专用 PostgreSQL。
- 增加隐私同意、数据导出、全部删除和账号注销闭环。
- 增加输入风险分类、危机响应和模型输出审核。
- 实现服务端强制执行的会员权益、订单与支付回调。
- 实现微信订阅消息、App 推送和 H5 明确降级。
- 实现收藏、资料编辑、情绪日历筛选和可靠聊天重试。
- 完成语义化控件、加载/错误/离线状态和基础无障碍支持。
- 升级有漏洞的生产依赖，补齐 CI、安全检查、备份、回滚和可观测性。

不在本轮范围内：在线心理诊断、人工心理咨询撮合、自建短信通道、社交社区、运营后台、复杂推荐系统。危机能力是风险提示与求助引导，不宣称替代医疗或紧急服务。

## 2. 分阶段交付

### 阶段一：P0 安全底座

阶段一完成后，系统可以安全识别用户、持久化敏感数据并处理高风险对话；平台凭据缺失时功能明确禁用，不产生模拟成功。

- 微信小程序 `wx.login`、App 微信 OAuth、H5 微信网页授权或手机号绑定的服务端登录交换。
- 短期 Access Token、可轮换 Refresh Token、退出登录和全设备会话撤销。
- 游客身份和登录后的显式数据迁移。
- PostgreSQL 数据模型、版本化迁移、JSON 数据迁移与回滚副本。
- 首次隐私同意、用户协议与第三方 AI 数据说明。
- 数据导出、账号删除申请、冷静期和到期物理清理。
- AI 输入风险分类、危机响应、输出审核、审计事件和速率限制。
- Express 与生产依赖升级，HTTPS 强制跳转和基础安全响应头。

### 阶段二：P1 产品闭环

阶段二完成后，页面上的会员、通知、收藏和账号能力均有真实后端行为。

- 免费版与会员版权益矩阵和服务端配额。
- 微信支付下单、签名、异步回调、订单查询、幂等处理和权益发放。
- 微信订阅消息、App 推送设备注册、提醒计划、时区和免打扰。
- 收藏创建、列表和取消收藏。
- 昵称、头像和偏好资料编辑。
- 情绪日历筛选与文本摘要。
- 聊天原消息 ID 幂等重试、超时状态和失败记录清理。
- 使用隔离测试用户和测试平台适配器的稳定 E2E。

### 阶段三：P2 发布质量

阶段三完成后，三端具备一致的交互状态、基础无障碍能力和可运维发布流程。

- 底部导航、菜单、会员卡片、情绪选项和 CTA 的语义化控件。
- SVG 图标系统替换字符字形图标。
- 全局骨架屏、错误重试、离线只读和空状态行动按钮。
- 图表文字摘要、数据列表、焦点样式、减少动态效果和 44px 触控目标。
- 微信与 App 正式 AppID、最小权限清单和合法域名校验。
- 不可变应用镜像、至少两个 API 副本、滚动发布、备份与恢复验证。
- 结构化日志、指标、告警和 AI/支付/通知成本观测。

## 3. 总体架构

三端继续共用 uni-app 前端和统一 API 客户端。前端只持有短期访问令牌，不保存平台 Secret、支付证书或 AI 密钥。API 服务按清晰边界拆分为身份、隐私、对话安全、业务、支付、通知和数据访问模块。

请求路径：

1. 客户端向微信或手机号提供方获取一次性授权凭据。
2. HeartNest API 使用服务端 Secret 向提供方换取平台身份。
3. 身份服务查找或创建 HeartNest 用户，签发访问令牌与轮换令牌。
4. 业务接口根据 HeartNest 用户 ID 查询 PostgreSQL，不再信任客户端设备 ID 作为身份。
5. AI 消息依次经过输入风险分类、业务配额、DeepSeek 适配器和输出审核。
6. 支付与通知通过接口化平台适配器调用；生产环境只加载真实适配器，测试环境显式加载测试适配器。

旧 `X-HeartNest-Device` 仅用于一次性游客数据声明。它不能直接读取用户数据；迁移需要当前游客凭据与已登录账号共同确认。迁移成功后记录来源并使旧游客凭据失效。

## 4. 身份与会话

统一身份模型支持以下提供方：

- `wechat_mini_program`：客户端提交 `wx.login` code，服务端换取 OpenID、UnionID 和 session key。
- `wechat_app`：客户端提交 OAuth code，服务端换取 OpenID 和 UnionID。
- `wechat_h5`：微信内浏览器使用网页授权 code。
- `phone`：H5 非微信环境使用受信任短信服务的服务端验证码；在短信提供方未配置前入口保持不可用。

同一 UnionID 自动关联为同一 HeartNest 用户。没有 UnionID 时，不自动合并不同 OpenID；用户需在已登录会话中主动绑定。所有绑定、解绑和合并动作写入审计事件。

Access Token 有效期 15 分钟；Refresh Token 默认有效期 30 天，每次使用后轮换并使旧令牌失效。服务端仅保存 Refresh Token 哈希。退出当前设备撤销当前会话，退出所有设备撤销用户的全部会话。

游客可以浏览陪伴者、选择情绪，并在明确额度内体验对话。游客不得购买会员、导出数据或启用跨端通知。登录后弹出数据迁移选择，不静默合并。

## 5. PostgreSQL 数据模型

核心表及职责：

- `users`：HeartNest 用户、状态、昵称、头像、时区、删除计划。
- `user_identities`：平台类型、平台主体标识、UnionID 密文或不可逆索引、绑定时间。
- `sessions`：Refresh Token 哈希、设备摘要、到期与撤销信息。
- `consents`：协议版本、隐私版本、第三方 AI 同意版本、同意时间和撤回时间。
- `guest_claims`：旧设备身份哈希、迁移状态和目标用户。
- `mood_records`：用户情绪、日期、摘要和来源端。
- `chat_threads`：用户与陪伴者的线程。
- `chat_messages`：客户端消息 ID、发送者、内容密文或受控存储、状态、风险等级和回复关联。
- `memories`：用户显式保存的记忆、来源消息、保留状态。
- `favorites`：用户收藏的消息或记忆，使用唯一约束防止重复。
- `memberships`：当前权益、来源、开始和结束时间。
- `payment_orders`：平台订单号、金额、币种、状态、回调摘要和幂等键。
- `notification_devices`：平台、推送 Token 密文、状态和最后活跃时间。
- `reminder_schedules`：提醒时间、时区、星期、免打扰和启用状态。
- `feedback`：用户反馈、处理状态和创建时间。
- `audit_events`：身份、安全、支付、隐私和管理员敏感动作，不保存完整对话正文。
- `data_exports`：导出任务状态、过期下载标识和完成时间。

所有表包含创建与更新时间。用户表采用稳定 UUID。消息以 `(thread_id, client_message_id)` 唯一约束实现幂等。支付回调以平台交易号唯一约束实现幂等。

## 6. 隐私与数据生命周期

首次进入必须展示 AI 性质、第三方处理方、数据用途、保存期限和危机能力边界。用户同意后记录具体文档版本；游客体验也必须同意最低必要的隐私说明。

账号页提供：

- 导出全部个人数据：异步生成 JSON 压缩包，下载凭据短期有效且只能使用一次。
- 删除全部数据：再次认证后进入 7 天冷静期，期间账号只允许取消删除或退出。
- 注销账号：冷静期结束后删除业务数据、身份绑定、会话和推送 Token；依法必须保留的支付审计仅保留最小字段并去标识化。
- 撤回非必要同意：关闭记忆、通知和后续 AI 处理，不影响依法保留的既有审计。

原始对话默认保留 180 天，用户主动保存的记忆保留至用户删除；审计事件默认保留 365 天。具体期限在隐私政策中保持一致。备份中的删除数据随备份保留期自然过期，并在恢复流程中重新应用删除墓碑。

## 7. AI 安全与对话可靠性

输入安全管线输出 `normal`、`distress`、`imminent_self_harm`、`imminent_harm_to_others` 四个等级。规则命中与分类器结果取更高风险等级。高风险流程不依赖生成模型自由发挥：

- `normal`：进入普通陪聊。
- `distress`：允许陪伴回复，同时增加温和求助建议。
- `imminent_self_harm` 或 `imminent_harm_to_others`：返回受控危机模板、当地紧急服务提示、联系可信任人员建议和继续陪伴入口；不提供可能强化伤害的细节。

DeepSeek 输出经过长度、敏感模式、医疗诊断、操控性表达和危险建议检查。未通过时使用受控安全回复，并记录不含完整正文的安全审计事件。日志不得记录 API Key、Token 或完整敏感对话。

聊天发送以客户端消息 ID 幂等。相同 ID 和相同内容返回既有结果；相同 ID 但内容不同返回冲突错误。失败重试复用原 ID。响应超时后消息保持可重试状态，不创建第二条用户消息。

服务端对游客、免费用户和会员分别设置每分钟及每日额度，并返回结构化限流信息。AI 上游不可用时历史内容仍可读，发送区显示明确重试状态。

## 8. 会员、支付与通知

权益由服务端计算，客户端只展示结果。初始矩阵：

- 游客：有限体验，不支持跨端同步、购买和通知。
- 免费用户：每日有限对话、近 7 日回顾、有限记忆数量。
- 会员：更高对话额度、长期回顾、更多记忆和会员提醒模板。

具体数字由服务端配置表提供，避免客户端硬编码。夜间视觉模式不作为虚假会员卖点；若没有真实差异则从文案移除。

支付流程：客户端创建订单，服务端生成微信预支付参数；客户端完成支付后仅显示“确认中”；服务端收到并验签平台回调后更新订单和会员权益。重复回调不得重复发放权益。未配置商户凭据时创建订单返回明确的 `PAYMENT_NOT_CONFIGURED`。

通知流程：

- 小程序保存用户主动授权的订阅模板授权，并由服务端发送订阅消息。
- App 注册推送 Token，并在退出登录或 Token 轮换时失效旧记录。
- H5 支持平台能力时注册 Web Push；不支持时显示不可用说明，不伪装成功。
- 所有提醒按照用户时区执行，并遵守免打扰；发送失败采用有限重试和死信记录。

## 9. 页面与无障碍

现有色彩、插图和玻璃卡片继续使用。新增或调整以下页面：

- 引导页增加 AI 边界、隐私摘要、协议勾选和游客入口。
- 登录/绑定页根据平台显示微信授权或手机号入口。
- 聊天页增加加载骨架、离线状态、限流状态、危机卡片和消息级收藏。
- 回顾页增加可点击空状态、筛选器、图表摘要与数据列表。
- 我的页实现真实收藏入口、资料编辑、账号与隐私入口。
- 会员页展示服务端权益、支付状态和恢复购买状态。
- 通知设置页增加时间、星期、时区、免打扰和平台授权状态。

交互规则：

- 底部导航使用可表达选中状态的 tab 语义。
- 所有点击目标使用 `button` 或等价跨端语义组件，提供可访问名称和禁用状态。
- 情绪选项表现为单选组，当前值不只依赖颜色。
- 字符字形图标替换为统一 SVG 图标；装饰图标对读屏隐藏，功能图标提供名称。
- 触控目标至少 44px，键盘焦点可见，支持减少动态效果。
- 图表提供等价文字摘要和逐日数据列表。
- 加载、错误、离线和空状态使用统一组件；每个错误状态提供一个明确恢复动作。

## 10. 部署、迁移与恢复

在 Sealos `ns-i61rahoe` 中创建 HeartNest 专用 PostgreSQL，不连接或复用 `widget-demo-db`。数据库凭据由 Secret 注入，应用账号不具备创建数据库或超级用户权限。

迁移顺序：

1. 创建 PostgreSQL、迁移 Job、备份存储和应用 Secret。
2. 执行结构迁移并启动只读校验。
3. 将现有 JSON 复制到带时间戳的只读备份。
4. 导入用户、偏好、情绪、线程、消息、记忆、会员状态和反馈。
5. 比较记录数量、用户级摘要和抽样内容哈希。
6. 在维护窗口短暂停写，导入增量并切换数据库连接。
7. 运行登录、资料读取、线程读取和健康检查。
8. 观察期内保留旧版本和 JSON 备份；回滚时恢复旧 Deployment 和只读数据副本。

应用改为不可变镜像，镜像使用 Node 20 的固定版本与摘要。API 至少两个副本并采用滚动发布；数据库和备份不随应用发布重建。Ingress 强制 HTTPS，并配置 HSTS、CSP、`X-Content-Type-Options` 和合适的 Referrer Policy。

每日执行加密逻辑备份，默认保留 30 天。每周在隔离数据库中自动恢复最近备份并执行数据完整性检查。恢复任务不得连接生产写端点。

## 11. 配置与凭据

生产环境需要以下 Secret：

- 微信小程序 AppID 与 Secret。
- 微信开放平台 App AppID 与 Secret。
- 微信 H5 网页授权配置。
- 微信支付商户号、API v3 密钥、商户私钥、平台证书与回调地址。
- App 推送提供方凭据。
- 短信提供方凭据；未配置时 H5 手机登录保持禁用。
- DeepSeek API Key。
- PostgreSQL 连接信息、Token 签名密钥、数据加密密钥和导出签名密钥。

代码库仅包含变量名称和配置说明，不包含真实值。生产启动时检查必需配置；身份主通道、数据库、Token 签名或数据加密配置缺失时拒绝启动。支付、推送、短信等可选能力缺失时只禁用对应入口。

## 12. 测试与 CI

测试层级：

- 单元测试：令牌轮换、权益计算、风险分级、隐私状态机、提醒时区和幂等键。
- API 集成测试：使用临时 PostgreSQL，验证身份、权限、迁移、支付回调、数据导出和删除。
- 平台契约测试：测试适配器模拟微信、支付、推送和 DeepSeek 的成功、失败、超时与重复回调。
- E2E：为每次运行创建隔离测试用户，覆盖引导、登录、聊天、重试、收藏、回顾、资料、会员和通知；禁止依赖固定 AI 文案。
- 构建测试：H5、微信小程序和 App 均进入 CI。
- 安全测试：生产依赖审计、Secret 扫描、HTTP 安全头、未授权访问和限流测试。
- 可访问性测试：H5 自动语义检查，加上微信开发者工具和 App 真机的键盘、读屏与触控检查清单。

部署后自动检查健康接口、数据库只读查询、测试身份交换和资料读取。部署检查不触发真实扣款、真实通知或真实 AI 消耗。

## 13. 可观测性与运营保护

API 输出结构化日志并包含请求 ID、用户匿名标识、路由、耗时和错误码，不包含敏感正文。指标至少包括请求错误率、延迟、AI 超时与拒绝、危机流程触发量、支付回调失败、通知失败、数据库连接和备份恢复状态。

告警按严重程度分级：登录全面失败、数据库不可用、支付验签失败激增和备份恢复失败为高优先级；单一 AI 上游超时通过降级提示处理并告警。服务端设置 AI 每用户额度和全局成本上限，达到阈值时不影响历史数据读取。

## 14. 验收标准

全部阶段完成需同时满足：

- 未持有有效令牌时不能读取、修改或导出其他用户数据。
- 微信三端身份可正确创建、绑定和合并，令牌轮换与撤销有效。
- 现有 JSON 数据迁移到专用 PostgreSQL，数量校验通过且具备已验证回滚路径。
- 用户可查看同意记录、导出数据、取消删除或完成账号注销。
- 高风险输入进入受控危机流程，危险模型输出不会直接展示。
- 会员权益只能由已验签支付回调或受控试用策略发放。
- 提醒在授权、时区和免打扰约束下发送；不可用平台明确提示。
- 收藏、资料编辑、情绪筛选和原消息 ID 重试均有真实持久化行为。
- H5、小程序和 App 构建通过；测试不依赖固定 AI 文案或共享线上数据。
- 关键控件具备语义、可见焦点、44px 触控目标和读屏名称；图表有文本等价物。
- 线上至少两个应用副本滚动发布，HTTPS 强制启用，备份恢复验证成功。
- 生产依赖中不存在未经风险接受的高危漏洞。

## 15. 实施约束

- 每个阶段必须使用测试驱动开发，并在独立提交中保留可回滚边界。
- 不在同一次部署中同时迁移数据库、切换身份主通道和启用真实支付。
- 不读取、输出或提交 kubeconfig、平台 Secret、支付证书或用户敏感数据。
- 不复用现有 `widget-demo-db`，不删除旧 JSON 数据，直至迁移观察期结束并完成恢复验证。
- 未取得相应平台凭据时，可以完成代码、测试适配器、配置校验和禁用态，但不得宣称真实平台验收完成。
