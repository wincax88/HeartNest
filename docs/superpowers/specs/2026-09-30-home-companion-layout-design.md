# HeartNest 首页陪伴区域布局优化设计

**日期：** 2026-09-30  
**范围：** 首页“今天谁陪你”横向人物卡与“最近夜间使用较多”提示卡  
**目标平台：** 微信小程序、H5、App

## 背景与问题

微信小程序会把 Vue 自定义组件编译为带独立宿主的组件节点。当前页面把尺寸和网格规则直接施加在 `CompanionCard`、`HnGlassCard` 等自定义组件宿主上，并在横向列表中使用兼容性不足的 `width: max-content`。在微信开发者工具中，宿主节点按内部按钮的最小点击尺寸收缩，导致：

- 人物卡宽度从设计的 `260rpx` 收缩到约 44px，图片和文字被挤成窄条；
- 夜间提示卡只占一小列，标题和说明逐字换行；
- 同一套样式在 H5、App 与微信小程序之间表现不一致。

## 选定方案

使用普通原生 `view` 作为稳定的布局边界，自定义组件只负责内容与交互。

### 人物卡区域

- 每个 `CompanionCard` 外增加一个原生 `view` 容器。
- 容器固定为 `260rpx × 360rpx`，设置 `flex: 0 0 260rpx`，不允许被横向布局压缩。
- `CompanionCard` 在容器内占满宽高；首张推荐卡继续使用粉色描边和推荐角标。
- 横向内容容器使用三端均支持的 `inline-flex`/固定子项方案，不依赖 `width: max-content`。
- 横向滚动继续保留，尾部留出页面内边距，让最后一张卡可以完整进入视口。

### 夜间提示卡

- 在 `HnGlassCard` 外增加一个全宽原生 `view` 容器，明确 `width: 100%`。
- 卡片内部保持两列：左侧固定圆形图标，右侧弹性文字区。
- 文字区设置 `min-width: 0`、正常横向排版与自然换行，标题和说明分别为一行及最多两行的视觉节奏。
- 保留现有夜景、玻璃背景、图标和文案，不改变业务含义。

## 保持不变

- 不修改情绪选择区、顶部品牌与问候、底部导航、背景图或主按钮。
- 不修改陪伴者数据、选择逻辑、聊天入口和路由。
- 不修改 API、状态管理或持久化逻辑。
- 不新增图片资产、字体或第三方依赖。

## 组件边界

- `pages/home/index.vue`：负责外层布局容器、滚动轨道与提示卡排版。
- `components/CompanionCard.vue`：负责单张人物卡的视觉内容与选择事件；补充占满父容器的根节点尺寸规则。
- `components/HnGlassCard.vue`：保持通用，不做可能影响其他页面的全局行为修改。
- `components/HnAction.vue`：保持通用点击与无障碍语义，不修改公共尺寸契约。

## 响应式规则

- 320–430px 手机视口：人物卡保持稳定宽度，至少显示一张完整卡和下一张卡的部分预览。
- H5 宽屏预览：继续限制在现有 `430px` 应用画布内，不拉伸人物卡。
- App 与微信小程序：使用相同 `rpx` 尺寸与滚动行为，不使用仅 Web 支持的布局值。
- 页面纵向滚动、人物区横向滚动互不阻塞。

## 状态与错误处理

本次不新增数据请求或错误状态。加载、离线、错误与空数据继续由现有 `HnAsyncState` 和 bootstrap store 处理。人物列表为空时，横向轨道不应产生异常宽度；夜间提示卡仍正常显示。

## 测试与验收

### 自动化

- 保留首页选择心情、打开陪伴者、进入聊天的现有测试。
- 增加结构测试，确认每张人物卡存在原生尺寸容器，夜间提示存在全宽容器。
- 增加小程序兼容性回归检查，禁止人物横轨继续使用 `width: max-content`。
- 运行单元测试、类型检查，以及 H5、App、微信小程序构建。

### 视觉验收

- 微信开发者工具中人物卡不再显示为窄条，图片、姓名、标语和标签可正常阅读。
- 夜间提示卡横向铺满内容区，不出现逐字竖排。
- H5、App、小程序三端保持相同信息顺序、间距层级和交互。
- 底部导航与主按钮不遮挡提示卡内容，页面可自然滚动到底部。

## 非目标

- 不重做首页整体视觉体系。
- 不改变人物卡数量、排序或推荐算法。
- 不新增轮播自动播放、分页指示器或新的业务入口。
