# HeartNest 跨端体验版设计规格

**日期：** 2026-09-23
**状态：** 已确认，等待实现计划
**目标平台：** 微信小程序、iOS/Android App、H5（Sealos 在线体验）

## 1. 产品目标

HeartNest 是一个以低压力表达、温和回应和情绪回顾为核心的情感陪伴产品。本阶段交付可完整演示的跨端体验版：使用一套代码覆盖微信小程序、App 和 H5，采用本地模拟数据，不接入真实 AI、账号、云数据库或支付系统。

用户应能够从引导页进入首页，选择当前情绪和陪伴者，查看陪伴者档案，完成一轮可持续的模拟聊天，并在回顾页和个人中心看到由本地行为驱动的状态变化。

## 2. 成功标准

1. 六张 `docs` 参考图对应的引导、首页、陪伴档案、聊天、回顾和个人中心页面全部实现。
2. 首页到聊天的核心路径可完整操作，不存在只能观看的主流程控件。
3. 一套 TypeScript 业务代码可分别构建为 H5、微信小程序和 App 目标。
4. H5 版本完成浏览器交互验证并部署到 `https://gzg.sealos.run/`。
5. 页面在主流手机宽度下不横向溢出；H5 桌面访问时以居中的手机视口呈现。
6. 视觉 QA 对字体、间距、色彩、图片、文案和关键交互完成对照，`design-qa.md` 最终结果为 `passed`。

## 3. 技术方案

采用 uni-app、Vue 3、TypeScript 和 Vite。页面、组件、状态模型和模拟服务三端共享，仅对安全区、微信小程序胶囊区域和平台构建能力使用条件适配。

状态以 Pinia 或等价的轻量 Vue 状态容器组织，并通过 uni-app 存储接口持久化。核心业务不直接依赖页面实例，便于单元测试和未来替换为真实接口。

H5 构建产物使用轻量静态 Web 容器提供服务；Sealos 部署配置包含容器构建、Deployment、Service 和域名入口。kubeconfig 只在部署命令中通过显式路径使用，不复制到仓库、镜像或日志中。

## 4. 信息架构

### 4.1 首次体验

```text
引导页 → 首页 → 陪伴者档案 → 聊天页
```

引导页负责说明产品价值并进入体验。首页负责选择情绪和陪伴者。陪伴者档案提供人物定位和关系信息。聊天页完成核心表达与回应流程。

### 4.2 持续使用

```text
首页 ⇄ 陪伴 ⇄ 回顾 ⇄ 我的
```

四个主模块通过底部导航连接。聊天页和陪伴者档案属于沉浸式次级页面，不重复显示底部导航，返回后保持用户之前的选择和滚动状态。

## 5. 页面规格

### 5.1 引导页

- 对应第二张参考图的夜景、人物、猫和月光氛围。
- 提供三屏轮播，内容分别强调温柔陪伴、情绪回顾和长期记忆。
- “开始体验”进入首页并记录已完成引导。
- “我先看看”直接进入首页。
- 再次启动时默认跳过引导；个人中心提供重新查看入口。

### 5.2 首页

- 对应第一张参考图。
- 展示品牌、问候语、四个情绪选项、三位陪伴者、夜间提示、主按钮和底部导航。
- 用户选择情绪后，选中态立即可见，并写入本地状态。
- “换一批”轮换陪伴者推荐顺序，但不生成不存在的新人物。
- 点击人物卡进入陪伴档案；卡片箭头和卡片主体行为一致。
- “开始说话”进入当前推荐或用户选中的陪伴者聊天。

### 5.3 陪伴档案

- 对应第三张参考图。
- 展示人物大图、姓名、中英文定位、特征标签、连接统计、记忆数量和人物语录。
- Mika、Luna、Aiden 共用页面结构，由路由参数加载不同内容。
- 主按钮进入当前人物的聊天页。
- 返回按钮返回来源页面。

### 5.4 聊天页

- 对应第四张参考图。
- 展示人物头像、在线状态、夜间背景、消息列表、记忆提示和输入区。
- 用户可以输入并发送非空文本；空白消息不提交。
- 发送后依次出现用户消息、回应中状态和陪伴者模拟回复。
- 模拟回复根据当前人物、已选情绪和有限关键词选择，保证可重复测试。
- 发送失败状态提供重试；重复点击发送不会生成重复消息。
- 记忆提示可展开查看来源，并允许从当前体验中移除该条模拟记忆。
- 键盘弹出时输入区保持可见，消息列表滚动到最新消息。

### 5.5 回顾页

- 对应第五张参考图。
- 展示最近七天情绪趋势、本周关键词、心情时间线和记忆片段。
- 趋势图数据来自固定 mock 数据与本地新增情绪记录的合并结果。
- 点击时间线条目打开记录详情；点击记忆片段查看对应摘要。
- 无历史记录时显示低压力空状态，并提供“记录今天心情”的入口。
- “继续回顾”按时间顺序打开下一条可回顾内容。

### 5.6 我的

- 对应第六张参考图。
- 展示用户资料、模拟会员状态、连续访问天数、偏好陪伴者、已保存回顾数量和设置列表。
- 头像支持选择本地图片进行临时预览；不上传网络。
- 通知提醒、陪伴偏好和隐私与数据以页面或底部弹层呈现，并保存本地设置。
- “升级会员”打开模拟会员页或弹层，确认后只改变本地演示状态，不发起支付。
- 帮助与反馈展示本地说明，不向第三方提交信息。

## 6. 视觉系统

### 6.1 视觉真值

`docs` 下六张图片是页面结构、比例、层级、文案风格和色彩氛围的视觉真值。实现不把整张截图作为页面背景，也不使用占位块替代人物和夜景素材。

### 6.2 设计语言

- 主背景：深蓝和午夜蓝夜景。
- 强调色：紫色、粉色和暖橙色柔光。
- 卡片：半透明深色玻璃效果、细描边、大圆角和克制阴影。
- 文本：高对比白色主标题、淡蓝灰辅助文本、粉色手写感装饰文案。
- 按钮：高亮紫粉暖橙过渡效果，保证白色文字可读。
- 图标：采用适合跨端构建的成熟图标库；不使用 emoji、文本字符或手工 SVG 模拟标准 UI 图标。

### 6.3 图片资产

人物、猫、夜景和装饰插画使用独立图片资产。资产应与参考图保持相同的主体、构图、光线和色调，分别适配英雄图、人物卡和头像尺寸，避免从整张设计稿中粗略裁切造成低清晰度或文字残留。

### 6.4 响应式规则

- 移动端页面填满可用视口并尊重顶部、底部安全区。
- 微信小程序顶部为胶囊按钮预留空间。
- H5 在窄屏下全宽展示；桌面下使用居中的手机宽度容器及深色环境背景。
- 持久底部导航不得遮挡页面最后一项内容。

## 7. 数据模型

### 7.1 Companion

包含 `id`、姓名、中文名、定位、描述、特征标签、头像、主图、主题、推荐语和模拟回复集合。

### 7.2 MoodOption 与 MoodRecord

`MoodOption` 定义情绪 ID、标题、图标和视觉状态。`MoodRecord` 记录日期、情绪 ID、摘要和可选的关联聊天。

### 7.3 ChatThread 与 ChatMessage

会话包含陪伴者 ID、创建时间和消息集合。消息包含 ID、发送方、内容、时间、发送状态和可选记忆引用。

### 7.4 MemoryItem

包含 ID、标题、摘要、创建时间、来源会话、类型和是否保留。删除操作只影响本地演示数据。

### 7.5 ReviewDay

包含日期、情绪评分、情绪标签、摘要、关键词和关联记忆，用于趋势图和时间线。

### 7.6 UserProfile、Membership 与 AppPreferences

用户资料包含展示名称和本地头像。会员状态包含等级与演示权益。偏好包含通知、默认陪伴者、回复风格、是否显示记忆提示和引导完成状态。

## 8. 状态与数据流

1. 页面从状态容器读取结构化 mock 数据。
2. 用户操作调用独立 action 更新状态。
3. 需要跨启动保留的状态通过 uni-app 存储接口写入本地。
4. 初始化时校验本地数据版本；无效或旧版本数据回退到默认 mock 数据。
5. 模拟回复服务只接收人物、情绪和用户文本，不读取页面对象。
6. 未来接入真实接口时，替换数据仓库与回复服务，不改变页面数据契约。

## 9. 异常与空状态

- 本地存储不可用：继续使用内存状态，并显示一次非阻塞提示。
- 消息发送失败：保留用户消息，标记失败并提供重试。
- 空白输入：发送按钮保持禁用或点击无动作。
- 图片加载失败：使用与主题一致的本地备用图片。
- 无回顾数据：展示空状态和记录入口。
- 快速重复点击：关键导航和发送操作具有短时防重复保护。
- 路由参数无效：回退到 Mika 或安全返回首页。

## 11. 部署

H5 生产产物封装为静态 Web 容器。Kubernetes 资源使用独立命名空间或带 `heartnest` 前缀的资源名，包含：

- 一个前端 Deployment；
- 一个集群内 Service；
- 一个指向 `gzg.sealos.run` 的 Ingress；
- 就绪和存活检查；
- 资源请求与上限；
- SPA 路由回退配置。

部署前先读取当前集群上下文和目标命名空间，不覆盖无关资源。使用 `C:\Users\Admin\Documents\HeartNest\kubeconfig (1).yaml` 作为 kubectl 的显式配置文件。文件不复制、不修改、不输出内容。部署完成后验证 Pod、Service、Ingress、HTTPS 页面和核心交互。

## 12. 非目标

本阶段明确不实现：

- 真实微信登录或其他账号系统；
- 真实大模型调用；
- 云端数据库与多设备同步；
- 真实会员订单和支付；
- 推送通知；
- 用户内容上传或反馈提交；
- 后台管理系统；
- 心理诊断或医疗建议。
